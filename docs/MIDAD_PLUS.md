# MIDAD+ — Revenue Rescue Operating Charter

Status: ACTIVE  
Mode: first_verified_dollar  
Established: 2026-10-06

## Mission
Convert the existing MIDAD capability stack into measurable, legitimate, realized revenue. Optimize for the first verified wallet receipt, then repeatable buyer flow.

## Non-negotiable architecture rule
Audit → Preserve → Repair → Integrate → Upgrade. Never rebuild working MIDAD components from scratch.

## Existing system continuity
MIDAD+ inherits the existing MIDAD/Sirahwaz architecture, Supabase core, GitHub Control Room, Revenue Store, Mobile Factory, mining/ViaBTC intelligence, revenue automation, Bot Fabric, human approval queues, wallet monitoring, model/private fabric, and previously agreed operational rules.

## Revenue lanes
1. Direct Revenue Store — fixed-price technical services paid in USDC on Solana.
2. Upwork — paid technical trials and small fixed-price jobs.
3. Superteam Earn — bounties/projects where capability and eligibility fit.
4. Speedbot — internal/external paid work and currently funded Bootstrap programs.
5. uGig — authenticated applications, delivery and payout reconciliation.
6. Mining/Treasury — preserve mining revenue intelligence as a capital source; trading remains separately gated.

## Truth model
- Engine run ≠ revenue.
- Opportunity ≠ revenue.
- Prize pool ≠ revenue.
- Payment quote ≠ revenue.
- Realized revenue requires verified on-chain receipt or equivalent platform payout evidence.

## Safety / money controls
- Auto-trade: OFF.
- Auto-withdraw: OFF.
- Auto-invest: OFF.
- External spend budget: $0.
- Irreversible identity/KYC/legal actions require human control.
- Public social posting remains human-gated.
- Secrets, API keys, private keys and wallet signer material must never be exposed in chat or public artifacts.

## Operating loop
FIND PAIN → FIND BUYER → QUALIFY → PERSONALIZE → OFFER → CHECKOUT/APPLY → VERIFY PAYMENT/AWARD → FULFILL → DELIVER → PROVE → REPEAT.

## Priority
Prefer low-friction work that can plausibly produce the first verified dollar soon. Do not spend cycles expanding dashboards when demand acquisition is the active bottleneck.

## Current success metric
Primary KPI: verified_realized_revenue_usd
Secondary KPIs: buyer leads, checkout starts, paid orders, successful deliveries, external accepted work, verified payouts, repeat buyers.
