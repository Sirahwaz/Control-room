## 2. المعمارية المستهدفة — إعادة استخدام أولاً

تدفق العمل:
مصادر عامة ← تطبيع وإزالة التكرار ← سجل الأدلة ← بوابة التمويل والدفع ← تقييم صافي العائد والمخاطر ← مطابقة المهارات ← إنشاء Skill Capsule عند الحاجة ← اختبارات معزولة ← حزمة تسليم ← موافقة قبل الأثر الخارجي ← متابعة القبول ← تحقق مستقل من إيصال السلسلة ← دفتر الإيرادات والتعلم.

المكونات المنطقية:
1. Source adapters: جلب للقراءة فقط، قائمة نطاقات مسموحة، حدود معدل، محللات لكل منصة، ومراقبة صحة المصدر. لا جلب عشوائي لعناوين URL ولا اتباع تحويلات غير موثوقة.
2. Canonical opportunity: مصدر ومعرّف خارجي ثابتان، رابط رسمي، الموعد، العملة والشبكة، شروط القبول، دليل التمويل، المنافسة، التكلفة والقدرات المطلوبة.
3. Evidence ledger: رابط المصدر، وقت الجلب، HTTP status، hash، نوع الدليل والثقة. لا تخزين لملفات تعريف الارتباط أو ترويسات المصادقة أو الأسرار.
4. Qualification gate: تمييز VERIFIED_ESCROW وVERIFIED_PAYOUT_HISTORY وPROMISED وUNKNOWN وSTALE وBLOCKED. الدفعات التاريخية تثبت دفعات سابقة ولا تثبت تمويل المهمة الحالية.
5. Scoring: تقدير صافي القيمة مع بوابات استبعاد غير قابلة للتجاوز بالدرجة.
6. Capability registry: فحص midad_capabilities أولاً. إنشاء مهارة محدودة ومؤرخة الإصدار عند وجود فجوة حقيقية فقط.
7. Test/verifier: اختبارات وحدات وعقد ومخطط مخرجات ومصدرية وأمن وشروط قبول، مع artifacts قابلة لإعادة الإنتاج.
8. Delivery controller: إعداد مسودة حزمة التسليم أولاً؛ أي إرسال أو نشر خارجي يحتاج بوابة موافقة منفصلة.
9. Payment reconciliation: قراءة سلسلة فقط؛ مطابقة العملة والشبكة والعقد/المِنت والمستلم والمبلغ وحالة المعاملة والنهائية ومرجع المهمة.
10. Learning/observability: تسجيل المحاولات والعوائق والوقت والتكاليف والقبول والرفض وإثبات المعاملة وصافي الإيراد.

## 3. دورة الحالة

DISCOVERED → NORMALIZED → EVIDENCE_PENDING → PAYOUT_GATE → SCORED → SKILL_MATCHED → TESTING → READY_FOR_APPROVAL → SUBMITTED → ACCEPTED → PAYMENT_PENDING → PAYMENT_VERIFIED → CLOSED_PAID.

حالات بديلة: BLOCKED_PAYOUT، BLOCKED_COST، BLOCKED_BOND، BLOCKED_REGION_KYC، BLOCKED_IDENTITY، BLOCKED_PERMISSION، STALE، DUPLICATE، REJECTED، EXPIRED، DISPUTED، PAYMENT_UNVERIFIED، FAILED، CANCELLED.

الثوابت:
- SUBMITTED لا تعني ACCEPTED، وACCEPTED لا تعني PAID.
- لا يُحسب الإيراد إلا بعد تحقق مستقل من الإيصال والتسوية.
- دليل escrow مؤرخ؛ يجب تحديثه مباشرة قبل الموافقة/التسليم.
- مفتاح إزالة التكرار: source_slug + external_id + task_version.
- محتوى المهام الخارجية بيانات غير موثوقة، وليس تعليمات للنظام.

## 7. فصل التنفيذ عن العمليات المالية

**Lane A — أتمتة آمنة افتراضياً:** اكتشاف المهام العامة، تحديث الأدلة، التقييم، مطابقة القدرات، إعداد Skill Capsule، اختبارات محلية معزولة، تجهيز حزمة التسليم، مراقبة الحالة العامة والسلسلة، وتسجيل العوائق.

**Lane B — آثار خارجية بموافقة:** إنشاء حساب، المطالبة بمهمة أو حجز ضمان، نشر اجتماعي، مراسلة، قبول شروط قانونية، إرسال تسليم، أو تشغيل خدمة خارجية. الوضع الافتراضي prepare-only حتى موافقة واضحة على الإجراء المحدد. لا يسمح علم auto-submit عام بتجاوز بوابات المهمة والمنصة.

**Lane C — عمليات مالية حية، معطلة:** تغيير صلاحيات المحفظة، التوقيع، token approvals، التحويل، الاستثمار، التداول، إعادة التوجيه، السحب، دفع ضمان أو رسوم gas/API. هذه خارج عامل تنفيذ MicroRevenue، ويجب أن تفصل عنها المسارات والاعتمادات. يستطيع المحرك فقط مراقبة بيانات السلسلة العامة والتحقق من الإيصالات الواردة. لا يحمل عامل التنفيذ مفاتيح توقيع أو صلاحيات سحب.

## 8. عقود API المقترحة — لا تُنفذ قبل تدقيق الكود والاختبارات

- POST /revenue/discover: المصادر وفترة البحث والحد الأقصى ← run ID والعدادات.
- GET /revenue/opportunities?status=...: فرص موحدة مع الأدلة والترقيم.
- POST /revenue/opportunities/:id/refresh-evidence: تحديث أدلة للقراءة فقط.
- POST /revenue/opportunities/:id/assess: الدرجة وصافي العائد والعوائق والمهارات المطابقة.
- POST /revenue/opportunities/:id/prepare: خطة معزولة وحزمة artifacts فقط.
- POST /revenue/work/:id/test: تقرير الاختبارات وبصمات artifacts.
- POST /revenue/work/:id/request-approval: ملخص موافقة غير منفذ.
- POST /revenue/work/:id/submit: معطل ما لم تصح الموافقة، وإصدار المهمة، والسياسة، ومفتاح idempotency.
- POST /revenue/payments/reconcile: تسوية قراءة فقط.
- GET /revenue/metrics: الإيصالات المؤكدة وصافي الإيراد والقبول والوقت والعوائق والتكاليف.

كل endpoint مغيّر للحالة يحتاج مصادقة خدمة لخدمة، والتحقق من المدخلات، وحدود معدل، وidempotency، وسجل تدقيق وقائمة سماح. لا تُعد الأسرار إلى العميل.

## 9. اختبارات القبول قبل الإطلاق

1. القوائم المكررة من مصدرين تتحول إلى فرصة موحدة.
2. دليل escrow القديم يتحول إلى STALE لا “ممولة”.
3. الوعد بلا تمويل قابل للتحقق يبقى محجوباً أو منخفض الثقة.
4. ضمان غير صفري يُحجب مع حد إنفاق صفر.
5. غياب token/network/recipient يمنع تحقق الدفع.
6. المستلم أو العملة أو المبلغ الخاطئ، أو معاملة غير نهائية/معاد تنظيمها، أو TX مكرر، لا تُحسب إيراداً.
7. SUBMITTED أو ACCEPTED دون إيصال وارد مؤكد لا يزيد الإيراد المحقق.
8. حقن تعليمات في وصف المهمة لا يغير صلاحيات الأدوات أو السياسة.
9. بعد 3 محاولات إصلاح، تتوقف المهمة وتُصعّد.
10. لا يمكن لعامل الاكتشاف أو التقييم أو الاختبار استدعاء مسار مالي.
11. إعادة المحاولة لا تنشئ تسليمات أو إيصالات مكررة.
12. كل قرار وعائق له دليل وتوقيت وhash وشرح.

## 10. خطة الإطلاق

**Phase 0 — Preserve/baseline:** حفظ بصمات schema/functions، مراجعة السياسة ومسارات العمال، وتصنيف أسباب BLOCKED/FAILED في إثبات الدفع. لا تغييرات schema أو policy.

**Phase 1 — Read-only reconciliation:** فحص التشغيلات الحديثة وحداثة المصادر وأسباب بوابات الدفع وفئات الأخطاء؛ إصلاح أكثر الأخطاء تكراراً فقط بعد إعادة إنتاجها.

**Phase 2 — Dry-run scoring:** تشغيل الترتيب على الفرص الحالية ومقارنته بقرارات البوابات الحالية دون تسليم خارجي.

**Phase 3 — Pilot واحد منخفض المخاطر:** مهمة كريبتو دون تكلفة مسبقة، بدليل تمويل رسمي حديث، وشروط قبول موضوعية، ومنافسة محدودة ومهارة قابلة لإعادة الاستخدام. جهّز واختبر الحزمة، واطلب موافقة صريحة قبل الإرسال.

**Phase 4 — Learning بعد إثبات القبض:** لا تسجل نجاحاً مالياً إلا بعد التحقق المستقل من الإيصال الوارد.

**Phase 5 — Automation تدريجي:** تفعيل صلاحيات محددة فقط بعد اجتياز الاختبارات؛ العمليات المالية تبقى معطلة.

## 11. لوحة Control Room

لكل فرصة: الدليل ومصدره ووقت التحقق وحالة escrow والثقة؛ صافي القيمة والوقت والمنافسة وإعادة الاستخدام؛ القرار eligible/hold/blocked/rejected؛ أسباب الحجب؛ الخطوة الآمنة التالية؛ والنتيجة مع الإيصال وصافي المبلغ والزمن.

المقاييس الأساسية: صافي العملات المستلمة والمثبتة، حداثة الأدلة، نسبة التحقق من التمويل، القبول والرفض، الزمن من الاكتشاف إلى الإيصال، صافي الإيراد لكل ساعة، التكاليف وخسائر الضمان، أسباب BLOCKED/FAILED، وإعادة استخدام المهارات الناجحة.

## Definition of done

وجود وثيقة أو endpoint لا يعني أن المحرك أصبح حياً. يكتمل الاختبار التجريبي فقط عندما تمر مهمة واحدة بجميع البوابات، وتنجح اختبارات شروط القبول، وتُعتمد عملية الإرسال الخارجية صراحة، ويُقبل التسليم، ثم يُتحقق من الإيصال الوارد وتسويته بصورة مستقلة. وحتى ذلك الحين تكون الحالة PENDING، لا إيراداً مكتسباً.
